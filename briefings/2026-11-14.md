## Worth Reading Closely

### Nvidia's board removed its founder — the mechanism matters more than the scandal

Jensen Huang built Nvidia from a gaming-GPU company into the hardware backbone of the AI industry over 33 years, and the board's decision to accept his resignation — rather than ride out the personal-life reporting with him still in place — was a deliberate governance choice, not a forced exit. The board explicitly said it has "no reason to believe" any national-security or company secrets were compromised by the relationships, which means this wasn't a security firing; it was a judgment call that the reputational and distraction cost of keeping him outweighed the disruption of removing him. CFO Colette Kress now holds both the CFO and interim-CEO roles simultaneously while the board, under newly appointed first-ever chair Harvey Jones, searches for a permanent successor from internal and external candidates (Trump has publicly floated Apple's Tim Cook).

What actually changes for anyone downstream of Nvidia: nothing in silicon ships any faster or slower this quarter — chip roadmaps are set years out, and Nvidia reports Q3 FY2027 earnings on schedule November 17. What's genuinely unsettled is judgment-call policy that used to run through one person: how aggressively Nvidia pushes back on export restrictions to China, how it prices and allocates scarce Blackwell supply between hyperscalers and smaller buyers, and how it responds to a separate, harder-to-verify claim this week that Chinese labs (DeepSeek, Moonshot AI, MiniMax, Ant Group) already got working access to export-controlled Blackwell chips based on hardware fingerprints found in their published model weights — a claim that shows access, not how it was obtained or whether it was legal. Huang also faces a Congressional hearing before Thanksgiving, which means the succession question and the export-control question are about to get asked in public, under oath, at the same time. For anyone building on top of frontier compute, the practical read is that pricing and allocation decisions that used to be made unilaterally are now more exposed to board-level and political pressure than they were two weeks ago. *(Confidence: Confirmed — reported identically across The Rundown AI/Tech, TLDR, TLDR AI, TAAFT, and Vaibhav Sisinty; the Blackwell-fingerprint claim specifically is Reported, sourced to one ex-OpenAI researcher's analysis, not independently verified.)*

### Self-hosted Claude Managed Agents: the tradeoff this actually removes

Anthropic's Managed Agents product normally runs as a hosted service: Anthropic operates the sandbox an agent executes code in, handles the credentials the agent uses to call tools, and stores the session history needed to resume or audit a run. That's convenient, but it means any company using it has to trust Anthropic's infrastructure with whatever sensitive data and credentials the agent touches — a dealbreaker for teams under data-residency rules, zero-data-retention contracts, or internal security policies that forbid sending operational data to a third party's servers. The new private beta keeps the same orchestration logic — sandboxing, credential handling, session history — but runs it inside the customer's own cloud account, integrated with whichever cloud provider they already use.

The mechanism-level change is a relocation of trust boundary, not a new capability: the agent doesn't get smarter or do anything a hosted agent couldn't already do, but the operator now controls the perimeter the agent runs inside, instead of extending that perimeter to include Anthropic's servers. The cost shifts the other way — the customer now owns the operational burden of running and patching that sandbox infrastructure themselves, work Anthropic used to absorb. For someone building smaller agent stacks on n8n rather than deploying enterprise infrastructure, the useful takeaway isn't "go self-host" — it's the architecture pattern underneath: orchestration logic, sandbox execution, and credential handling are three separable layers, and keeping credentials out of whichever layer an LLM can directly influence is the same discipline a self-hosted enterprise deployment is built around at scale. *(Confidence: Confirmed — announced on Anthropic's own resources page, reported via TLDR AI.)*

## Agents & Automation Watch

Replit Agent can now make purchases and run ad campaigns on a business's behalf: it uses Visa's and Stripe's "Link" integrations to execute supply purchases with spending controls, and separately analyzes a business's existing content to draft and run Google Ads campaigns. This is a step past agents that draft or recommend — it's an agent authorized to move money and spend budget directly, which is the exact capability that makes scoped permissions and spend caps non-optional rather than nice-to-have. *(TLDR AI)*

A published benchmark of Google's Agent Anomaly Detection tool, run against external test sets the tool wasn't tuned on, found it flagged 87% of executed harmful instructions, with particular strength at catching goal hijacking and tool misuse. Its weak spot is poisoned-memory attacks, and its false-alarm rate climbs to 16% specifically on high-impact tool calls — meaning the tool that's supposed to catch the worst actions is also the one most likely to cry wolf on them. Worth tracking as a signal for how mature agent-monitoring tooling actually is, not just how it's marketed. *(TLDR AI)*

A widely discussed engineering post argues that AI-written code "slop" — functional but poorly reasoned code — hasn't gone away, it's moved up the stack. Raw syntax-level sloppiness is down, but frontier coding agents still show poor foresight about how their code will actually be used downstream, weak abstraction choices, and a tendency to reimplement logic that an existing library already provides instead of reusing it. The practical implication for anyone reviewing agent-generated code: the bugs worth looking for now are architectural, not syntactic. *(TLDR)*

## One Thing to Learn

An AI system called Darmok entered a cryptic-crossword championship that's run since 1970 and beat every human competitor, solving all seven puzzles without an error and finishing the final 3 minutes 13 seconds ahead of the human champion — then held 99.84% accuracy on 1,261 daily clues published after its underlying models finished training, ruling out memorization as the explanation. The part worth 20 minutes isn't the puzzle-solving — it's the reliability architecture underneath. Darmok runs each clue through three separate AI models and writes in the answers it's most confident about first, because those confirmed letters constrain and simplify the harder remaining clues, the same way a human solver uses easy answers to unlock hard ones. During the final, its primary underlying model slowed sharply under load, and Darmok automatically rerouted to its backup models mid-competition without losing accuracy.

That's three transferable patterns in one system: ensemble multiple models instead of trusting one, order outputs by confidence so easy wins inform hard cases, and build automatic failover so a degraded model doesn't take the whole pipeline down with it. None of this requires crossword-specific infrastructure — it's a direct blueprint for making any multi-step n8n agent chain more reliable: run a cheap confidence check before committing to an answer, resolve the parts you're sure about first, and wire in a fallback model so one provider's slowdown doesn't stall the whole workflow. *(Source: arXiv, via TAAFT)*
