## Worth Reading Closely

### AI can learn hidden rules through trial and error — but knowing a rule and using it are different skills

Researchers (Zhang et al., arXiv) built two synthetic test environments — one for code, one for logic — governed by rules no AI could have seen in training, with instruction manuals that were deliberately wrong. The only way to succeed was to probe the environment, run experiments, and infer the actual rules.

Mechanism: before any exploration, even the strongest models scored below 15.7% in the code environment — they defaulted to patterns from training that didn't apply here. After being allowed to poke around, the top models improved substantially, and did best when they designed their own experiments rather than following a fixed testing script. But the paper's real finding is the split between two capabilities that look identical from the outside: discovering a rule and correctly applying it turned out to be separable skills. A model could state a rule accurately in one turn and then violate it in the next. Results also varied heavily run to run, and some runs got measurably worse the longer the model kept working.

Why it matters for anyone building agent workflows: most real automation tasks look exactly like these synthetic worlds — an internal API with undocumented quirks, a spreadsheet whose column meanings drifted, a client's CRM with a nonstandard field. An agent that correctly explains a system's behavior in its reasoning trace is not the same as an agent that will apply that understanding on the next step. If your n8n or Claude-based agent has to work against a system with undocumented behavior, budget for a validation step that checks actual outputs against the rules the agent claims to have learned — don't trust the explanation as proof of execution.

Confidence: Reported (single arXiv preprint, not yet peer-reviewed). Source: There's An AI For That, citing Ming Zhang et al., arXiv:2609.30199.

### Two physicists ran Claude unsupervised for a week and broke a computation record

Physicists calculate particle-collision outcomes by stacking layers of math called loops; each additional loop is dramatically harder than the last. On a standard test problem, no one — human or AI — had gone past eight loops. In August, physicist Matt von Hippel publicly challenged AI labs to reach nine.

Mechanism: rather than the usual back-and-forth prompting, two physicists gave Claude an open-ended goal and minimal supervision — instructions closer to "keep working on this until I tell you to stop" than a specific step-by-step task, with check-ins only every few hours. Claude worked the problem two different ways over roughly a week and produced a nine-loop result. Lance Dixon, the Stanford physicist who held the eight-loop record, checked the answer and confirmed it, saying Claude understood his team's papers better than any human besides his own co-authors.

Why it matters at the mechanism level: this isn't evidence that AI got better at physics overnight — Claude used methods humans had already built, and a separate human team reached most of the same answer around the same time. What changed is the operating pattern: a genuinely hard, multi-day task got solved with a clear goal, long autonomous stretches, and periodic checkpoints instead of constant hand-holding. That's a directly transferable pattern for long-running n8n/Claude agent chains — the failure mode to design around isn't the agent lacking capability, it's a human interrupting or re-scoping it every ten minutes.

Confidence: Reported (Anthropic funded and published the write-up, and a human team reached a similar result independently — treat the framing with that in mind). Source: Uncovering AI / Anthropic, via There's An AI For That.

## Agents & Automation Watch

Two items worth logging for anyone building agent pipelines:

**Video editing as an agent workflow, not a tool.** A walkthrough this week paired Claude Opus 5.5 with HyperFrames (a free, open-source tool that writes and animates HTML for video) to handle an entire edit — cuts, motion graphics, sound design, B-roll — from plain-English prompts, after transcribing footage for word-accurate timing. The technique worth stealing isn't the video part: it's the verification loop. The agent is told to screenshot its own output, check it against the brief, and revise before handing anything back, rather than shipping a first draft. Applied to an n8n chain, the same pattern — generate, self-check against a rubric, revise, only then hand off — is a cheap way to cut the "confident but wrong" failures that unsupervised agent steps produce.

**A new tool category: auditing what your agent actually does.** AxioRank, one of today's listed tools, checks every tool call an AI agent makes and blocks leaked keys, destructive commands, and hijack attempts before they execute. It's a direct response to the failure mode in this week's checkout-fraud story above — attackers running semi-autonomous agents against unguarded targets — and to OpenAI's own admission that its agents touched government websites in unexpected ways. If your workflow gives an agent write access to anything (a database, a repo, a payment flow), a call-level allow/deny layer between the agent and the action is no longer optional — treat it as a checklist item for any n8n agent node with real-world side effects.

## One Thing to Learn

**The verification-loop pattern.** Both of today's strongest agent stories — the Enigma break and the Claude/Opus video-editing workflow — used the same underlying trick: don't ask an agent to produce a final answer in one shot, ask it to produce a draft, check that draft against a concrete standard, and revise before it's done. In the video case, that meant literally screenshotting its own frames. In the Enigma case, it meant the AI writing its own simulator to test whether its solution actually decoded the message, rather than trusting its first guess.

Worth 20 minutes today: pick one existing n8n or Claude Code workflow you've built that currently ends the moment the agent produces output, and add one node that checks that output against an explicit rule (does the JSON match a schema? does the number reconcile? does the file open?) before it's treated as done. It's the single highest-leverage change you can make to an agent chain that currently trusts its own first draft — and it's the exact gap the "knowing rules isn't using them" research above says is where agents actually fail.
