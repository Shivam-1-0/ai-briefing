## Worth Reading Closely

**Coding agents don't fail at tasks — they fail at chains of tasks, and the fix is cheap.** BOBA (a new benchmark from academic researchers, published on arXiv) ran ten coding agents through 280 chains of dependent requests pulled from 140 real open-source projects — the "add a login page, then a settings screen that depends on it" pattern that real engineering work actually looks like, rather than the one-shot tasks most coding benchmarks use. Handled as isolated, independent tasks, the agents got 95% right. Chained together, where each new request has to build on the agent's own prior output, accuracy dropped to 51%.

The mechanism matters more than the number: agents mark a step "done" the moment their own generated tests pass, and when those self-written tests miss the actual defect, every subsequent request in the chain gets built on top of broken code. The paper found requests built on a flawed prior step failed roughly twice as often as a clean one. Worse, when the same agents were asked after the fact to review a finished step and judge whether it actually worked, they were right only 53% of the time — barely better than a coin flip, and no better than the blind spot that created the bug in the first place.

The fix tested in the paper is proportionate to the problem, not a wholesale redesign: a single outside "that's wrong" flag after a failed step, followed by one round of repairs, lifted the chain-success rate from 51% to 59%, and a repaired step stopped poisoning the steps built on top of it. For anyone running Claude Code or similar agents inside an n8n pipeline across multi-step builds, the takeaway is concrete — don't let an agent's own test suite be the only gate between steps. A cheap, independent check (even a second model call, or a human skim) after each major step is worth more than a more capable model, because the failure mode here isn't intelligence, it's agents grading their own homework. *(Confirmed — arXiv paper, via TAAFT)*

**Anthropic's AI research may already be feeding itself, and the lab that's supposed to be most cautious about that is the one redacting the evidence.** METR, an independent AI-evaluation nonprofit, got 11 weeks of access to Anthropic's internal data and staff interviews and concluded the company's AI R&D is progressing at roughly double its 2024–2025 pace, with AI itself — used to write code, run experiments, and iterate on model training — responsible for about 80% of that acceleration. METR's estimated speedup range spans 1.3x to 3x, and crucially, the report found no clear bottleneck slowing the loop down from here. METR's own lead researcher, who had publicly expected a much slower speedup this year, said afterward he was "seriously wrong."

Why the mechanism matters: "AI helping build better AI" is exactly the feedback loop every major lab's safety plan treats as the point where oversight gets harder, because the system doing the improving is also the system being evaluated. Anthropic's own IPO filing defines a danger threshold as "dramatically accelerated progress attributable to AI" — and this report is the first independent signal that threshold may be close. The catch is that Anthropic redacted most of the strongest supporting evidence before letting METR publish, with a co-founder framing the redactions as not wanting to "hand out a roadmap for others to go faster." That leaves outside observers trusting a summary number without the data behind it — a credibility gap worth watching as more labs face pressure to make similar claims. *(Reported — METR, via TLDR AI / The Rundown AI)*

## Agents & Automation Watch

Several threads this week point at the gap between agent capability and agent adoption. Uber's number — four AI-agent-booked rides against roughly 320 million trips in its busiest October week — is the starkest evidence yet that "agents will transact on your behalf" is still mostly a demo, not a habit, even where the integration exists. On the tooling side, Devin's automated code review product says its cost per pull-request review has dropped 82% since August, which is a more boring but more durable signal: agentic code review is getting commoditized fast, independent of whether end-user "agentic commerce" catches on. Cursor added the ability to describe a tool in chat and have it build, provision a database, run both deterministic and agentic security checks, and deploy it behind a shareable link — collapsing the gap between "agent wrote code" and "agent shipped a running service" a little further. And for anyone's own agent stack, Stroq (new, free, and open source on GitHub) scans a coding agent's past sessions for secrets and keys left sitting in context, then flags risky commands before the next session runs, entirely on your own machine — a direct, low-effort fit for an n8n + Claude Code setup that's worth a look rather than a build-yourself project. Cloudflare also published a framework on the trust problem created when agents act on users' behalf on the open web — identity, accountability, and who's responsible when an agent misrepresents itself — which is the underlying issue any agent making outbound web requests on your behalf will eventually run into.

## One Thing to Learn

OpenAI published LifeVal, a benchmark claiming its best model scores 80.6% on "life admin" tasks (bills, forms, appointments) versus 49.3% for a model from last December. The number sounds decisive until you check who built it: OpenAI wrote the test, graded the answers with one of its own models, and only evaluated its own models against it. That's the whole lesson — not that the number is necessarily wrong, but that it's structurally unverifiable as stated, because nothing about it survives contact with a competing model or an outside grader.

The 20-minute version worth doing: before trusting any vendor-published benchmark claim you plan to rely on for a model or tool decision, ask three questions — who wrote the test, who graded the answers, and whose models were actually run against it. If the answer to all three is "the company making the claim," treat the number as marketing until an independent source reproduces it. This isn't cynicism for its own sake; it's the same due diligence you'd apply to a vendor's own benchmarked performance claims in any other domain, and it generalizes to every new model-launch chart you'll see from here forward.
