What actually changes if the board acts: Nvidia has no bench for this. There's no successor named in any of the reporting, and no public playbook for replacing a founder-CEO who has personally set product strategy, investor messaging, and customer relationships for over three decades. The mechanism that makes this a finance story and not just a tabloid one is concentration — nearly every major AI lab trains on Nvidia chips, so a disorderly leadership change at the top of that supply chain is a risk that propagates outward to every company building on it, including Anthropic, whose IPO was reportedly oversubscribed by several times its offered shares this same week. A rocky transition at Nvidia doesn't just hit Nvidia's stock; it's a variable in the cost and availability of compute for everyone downstream of it. *(Confidence: Reported — neither Nvidia nor Huang has confirmed a departure; this is board deliberation reported by WSJ and NYT, relayed by The Rundown AI and TLDR AI.)*

### A hobbyist's 48-agent search shows a repeatable pattern for turning public data into expert-grade work

The sequence matters more than the discovery itself. A traveler asked Gemini a history question near Machu Picchu, got curious what a century-old explorer would do with modern tools, and put that exact question to Gemini, ChatGPT, Claude, and Grok — all four independently suggested lidar. That's a usable technique on its own: when you don't know the right method for a problem, asking multiple models the same open-ended question and checking where they converge is a cheap way to find out, before you've committed to an approach. He then fed publicly available lidar scans (including NASA's) to 48 agents overnight, which classified 463 square miles of jungle terrain one tile at a time, flagging candidate structures and discarding natural hills. A second pass had the agents cross-check which flagged villages weren't in any existing register — narrowing a sprawling, unstructured search into one hilltop site with a plaza and a 26-to-39-foot pyramid.

The part worth noting for anyone designing agent workflows is what came after detection: the agents told him who to contact and wrote the report in Spanish, a language he doesn't speak, closing the gap between "found something" and "did something useful with it" without him personally handling either the domain expertise or the language barrier. Mexico's heritage agency confirmed the site wasn't in their records — but a later check turned up a 2025 academic study that had already mapped the same hilltop, downgrading the result from a new discovery to an independent rediscovery. That's the honest caveat: the agents reached the same conclusion experts already had, with zero formal training, not a conclusion experts had missed. The reusable part isn't "AI finds lost cities" — it's fan out a large, low-stakes classification task across many agents against public data, then hand the agents the follow-through work (translation, procedural know-how) that isn't the bottleneck skill. *(Confidence: Confirmed as a process, from the researcher's own published account; the discovery itself is a confirmed rediscovery, not a confirmed new find. Via The Rundown AI and TAAFT.)*

United Airlines' move to block AI agents from its booking flows is the clearest regulatory-flavored signal yet that travel and transaction sites are starting to treat autonomous agents as a liability to defend against by default, not a channel to court — a split from Expedia and Booking.com's opposite bet. On the tooling side, Google shipped A2UI 1.0, an open protocol that lets agents respond with interactive native UI screens instead of plain text, with renderer SDKs now available for web, Android, iOS, and agent SDKs for Python, TypeScript, and Dart. Attio shipped Custom Agents that run with exactly the permissions of a named person rather than a standing elevated role, with a visible log of what each agent read and decided and the ability to pause or replay any run — a narrower, auditable take on agent permissioning than most CRM agent rollouts. ## One Thing to Learn

TLDR AI flagged a concrete benchmark on what tool-exposure method actually costs in an agent's context window: on Sonnet 5.5, a simple task consumed 59,417 tokens when tools were exposed via a default MCP setup, versus 1,421 tokens through a CLI and 3,315 tokens through a packaged skill. Deferring tool definitions with a tool-search pattern — loading a tool's full schema only when it's actually needed, instead of dumping every connected server's entire tool list into context up front — cut the upfront cost to under 600 tokens.

This is worth 20 minutes because it's a direct cost-and-reliability lever for exactly the kind of stack this briefing assumes: an n8n workflow calling Claude with several MCP servers attached pays that MCP token tax on every single run, whether or not the task uses most of those tools. The fix isn't "use fewer tools" — it's architecting tool access so unused definitions aren't loaded by default, which is the same principle behind how tool-search and skill-based designs keep an agent's context lean without cutting its actual capability.

## Rotating: Tools Worth Trying

**Atuin Threads** keeps Claude Code and Codex sessions in one searchable history across every machine you run them on, free and open source on GitHub. The mechanism is a synced session log rather than a local-only shell history, so a task started on a desktop can be picked back up, searched, and referenced from a laptop without re-explaining context. For anyone running Claude Code as part of an n8n-triggered workflow — kicking off a coding agent from an automation and later needing to audit or resume what it did — this solves a real gap: n8n itself doesn't give you a searchable record of what a Claude Code session actually did across invocations, and Atuin Threads is a thin, free layer that does. **Verdict: Adopt.** It's free, open source, sits underneath the agent rather than inside the workflow, and costs nothing to try against a stack that already runs Claude Code and GitHub.

**A2UI 1.0** lets an agent answer with an interactive screen — native buttons, forms, and components — instead of a wall of text, with open-source renderer SDKs for web, Android, and iOS and agent-side SDKs in Python, TypeScript, and Dart. The appeal for an agent stack is obvious: a workflow step that currently returns plain text could instead return something a person actually clicks through. The catch is where the complexity sits — A2UI needs a renderer embedded in whatever surface displays the output, which means it's built for teams shipping their own app or chat surface, not for a workflow whose output lands in Slack, email, or a spreadsheet, which is the common case for an n8n automation. **Verdict: Skip, for now.** It's worth watching once (or if) a lightweight renderer shows up that can sit behind a webhook n8n can call, but today it asks for app-level integration this kind of stack doesn't have a slot for.

**Grok Bot 1.0's Team Bots** turn xAI's assistant into something a whole team can publish and talk to inside Slack, Microsoft Teams, and video meetings, with admin controls and shared connectors. It's a capable, well-integrated product if the team already lives in Slack or Teams and wants one shared assistant. But it's a closed, vendor-hosted agent with no documented API or webhook path for triggering it from, or feeding its output back into, an external automation — which is the opposite of what an n8n-based stack needs, since the whole point of n8n is composing steps across tools, not adopting a single closed one. **Verdict: Skip.** Reasonable for a team that wants one shared Slack bot and nothing more; not composable into a broader automation pipeline.
